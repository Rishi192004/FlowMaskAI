1. EXECUTIVE SUMMARY & PROJECT PURPOSE
--------------------------------------------------------------------------------
FlowMind is an enterprise-grade Process Mining and Operational Analytics Platform.
Its core mission is to ingest raw enterprise event logs (specifically Purchase-to-Pay / P2P),
reconstruct actual as-executed business workflows, quantify operational bottlenecks,
detect process deviations and compliance breaches against a reference standard, and 
provide evidence-based recommendations grounded strictly in computed metrics.

Target P2P Reference Flow:
  [Purchase Requisition] ──> [Manager Approval] ──> [Purchase Order Created]
       ──> [Goods Received] ──> [Invoice Received] ──> [Invoice Verified]
       ──> [Payment Completed]

  - Comprehensive PRD, system architecture, PM4Py pipeline contracts, database schema,
    API specifications, and phase-wise acceptance criteria (FlowMind_Planning.md).

• Phase 1 — Scaffolding & Backend Foundation (Commit: e8767cc)
  - FastAPI app factory with CORS, structured JSON logging, and custom exceptions.
  - JWT authentication (register, login, refresh, /me) via Passlib (Bcrypt) and Python-Jose.
  - SQLAlchemy 2.0 ORM + Alembic migrations for PostgreSQL.
  - Health check probe (/api/v1/health) and Project lifecycle CRUD endpoints.
  - Docker Compose orchestration (Postgres, Backend, Frontend).

• Phase 2 & 3 — ETL & Event-Log Processing Pipeline (Commit: 65c65d3)
  - Alembic migration (0002) for datasets, events, etl_executions, and data_quality_issues.
  - Streaming CSV delimiter detector and automatic column synonym mapping.
  - Data normalizer (activity acronym preservation, UTC timestamp parsing).
  - Anomaly detector & validator (duplicate signatures, out-of-order timestamps, null values).
  - Chunked ETL loading pipeline (CHUNK_SIZE = 5000) with batch database flushes.
  - Synthetic 102,000-event P2P sample dataset (data/sample/p2p_100k_events.csv) with
    realistic process paths (standard, skipped approval, rework, early invoicing).

• Phase 4 — Operational Analytics Engine (Commit: 65c65d3)
  - High-performance SQL queries + Pandas analytical service:
    * Case throughput (total, completed, open/in-progress).
    * Cycle time percentiles (min, max, mean, median, P50, P75, P90, P95, 10-bin histogram).
    * Stage-by-stage waiting time rankings and bottleneck identification.
    * Rework rates and activity repetition loops.
    * SLA compliance tracking (target vs actual duration).
    * Multidimensional vendor performance (spend, case count, avg duration, breach rate).
  - Analytics endpoints exposed at /api/v1/analytics/*.

• Phase 5 — Process Mining Engine via PM4Py (Commit: 6c77bbf)
  - DB to PM4Py EventLog and DataFrame converter.
  - Directly-Follows Graph (DFG) discovery with edge frequencies and transition durations.
  - Inductive Miner Petri Net derivation with structural fallback.
  - Trace variant discovery, Pareto analysis, and outlier detection.
  - Differential process comparison across departments, vendors, or time periods.
  - Process mining endpoints exposed at /api/v1/process/*.

• Phase 6 — Conformance Checking & Deviation Detection (Commit: 6d6301f, cfd299b)
  - Configurable P2P reference workflow rules (app/conformance/rules.py).
  - Token replay and trace alignment heuristic engine (app/conformance/engine.py):
    * Detects Skipped Manager Approvals (HIGH severity).
    * Detects Early Invoicing / early invoice verification before goods receipt (HIGH severity).
    * Detects Skipped Invoice Verification before payment (HIGH severity).
    * Detects Repeated Approvals / rework loops (MEDIUM severity).
    * Detects Incomplete / Abandoned cases without payment (MEDIUM severity).
    * Detects Out-of-order activities including Maverick Buying (MEDIUM severity).
    * Detects Unexpected non-standard activities (MEDIUM severity).
    * Computes token-replay fitness approximation scores (0.0 to 1.0).
  - Conformance endpoints exposed at /api/v1/conformance/*.

• Phase 7 / Frontend Integration (Commit: 044d635)
  - Created frontend/src/main.tsx and frontend/src/App.tsx with full layout and routing.
  - Created frontend/src/index.css with dark slate/navy theme and custom scrollbars.
  - Implemented VendorPerformance.tsx with spend and SLA distribution charts.
  - Implemented AIProcessAssistant.tsx with interactive grounded chat and recommendation feeds.
  - Fixed relative import paths across all 10 page views.
  - Verified full TypeScript compilation and production build (tsc && vite build).

• Phase 8 / Grounded Recommendations Engine (Commit: cfd299b)
  - Implemented complete backend/app/ai module:
    * backend/app/schemas/ai.py: Pydantic schemas for RecommendationItem, RecommendationsConfig, RecommendationsResponse.
    * backend/app/ai/rules.py: 8 independent, configurable rule evaluators:
      1. SKIP_APPROVAL (Compliance)
      2. EARLY_INVOICE (Financial Risk)
      3. SKIP_VERIFICATION (Compliance)
      4. HIGH_REWORK (Quality)
      5. APPROVAL_BOTTLENECK (Efficiency)
      6. LOW_FPY (Quality)
      7. HIGH_ABANDONMENT (Efficiency & Risk)
      8. SLA_BREACH (Compliance)
    * backend/app/ai/engine.py: generate_recommendations() orchestrates analytical inputs,
      evaluates rules, and ranks action items by estimated impact score.
    * backend/app/api/v1/endpoints/ai.py: GET /api/v1/ai/recommendations endpoint.
    * backend/tests/test_recommendations.py: Comprehensive unit and integration test suite.
    * frontend/src/api/ai.ts: Client integration feeding real backend recommendations directly
      into the AI Process Assistant page.
